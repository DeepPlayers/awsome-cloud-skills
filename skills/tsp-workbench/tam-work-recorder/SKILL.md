# TAM 工作记录

## 触发场景

用户输入工作记录时，如"客户XXX做了YYY"、"今天帮客户解决..."等。

## 工作流程

### 1. 解析输入

提取：客户名、工作内容、工作分类（自动）、时间（默认1小时）、日期（默认当天）

**工作分类标准：**

| 分类 | 关键词 | 场景 |
|------|--------|------|
| 基本盘 | 故障、排查、修复、支持、咨询、巡检 | 日常技术支持 |
| 搬栈 | 迁移、上云、搬迁、割接、数据迁移 | 业务上云、系统迁移 |
| AI | AI、模型、训练、GPU、智算、大模型 | AI项目支持 |
| 架构优化 | 架构、优化、改造、升级、性能、调优 | 架构设计、性能优化 |

### 2. 整理表述

**单条记录格式（4个字段）：**
```markdown
- **客户简称**：XXX
  - **工作分类**：基本盘/搬栈/AI/架构优化
  - **投入小时数**：X
  - **工作内容**：详细描述
```

**整理原则：**
1. **工作分类**：自动识别，单独成行
2. **投入小时数**：默认1，单独成行
3. **工作内容**：
   - 一句话扩写成2-3句
   - 口语转正式用语："帮客户"→"协助客户"、"看了下"→"查看"
   - 使用完整句式，技术术语规范

### 3. 写入文件

**文件路径：** `/Users/yaohao/agent/工作提效/工作记录/work-logs/work-log-YYYY-MM-DD.md`

**写入后验证（必须执行）：**
1. 使用 `ls -la` 命令检查文件是否成功创建
2. 如文件不存在，需重新尝试写入或排查权限问题
3. 向用户明确告知保存路径，便于用户查找

**文件格式：**
```markdown
# 工作日志 - YYYY年MM月DD日

## 今日工作记录

### 基本盘
- **客户简称**：阿里
  - **工作分类**：基本盘
  - **投入小时数**：2
  - **工作内容**：响应客户ECS异常告警，协助故障诊断与排查，定位并修复问题

### 架构优化
- **客户简称**：银泰
  - **工作分类**：架构优化
  - **投入小时数**：1
  - **工作内容**：与客户会议沟通，讨论系统架构设计方案及最佳实践
```

**规则：**
- 按分类分节，无记录则省略
- 同一客户多条记录分别列出
- 追加到当天文件

## 示例

**输入：**
> 刚帮阿里云客户处理了一个ECS的问题，大概花了2小时

**输出：**
```markdown
### 基本盘
- **客户简称**：阿里
  - **工作分类**：基本盘
  - **投入小时数**：2
  - **工作内容**：响应客户云服务器ECS异常告警，协助进行故障诊断与排查，定位并修复系统问题，恢复业务正常运行
```

## 注意事项

1. 中文输出，正式专业
2. 内容必须扩写（2-3句）
3. 四个字段缺一不可
4. 工时纯数字，不加"约"
5. 技术产品用全称（如"云服务器ECS"）
6. **写入文件后必须验证**：调用 Bash 工具检查文件是否成功创建，确认后再告知用户保存路径
