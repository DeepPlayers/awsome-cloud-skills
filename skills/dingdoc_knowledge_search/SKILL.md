# 钉钉知识库智能检索 Skill V3

## 触发条件

当用户输入以下命令时触发：
- `/search-knowledge <问题>` - 搜索知识库
- `/search-knowledge --help` - 显示帮助信息

## 环境要求

**⚠️ 前置依赖**：本 Skill 依赖钉钉文档 MCP Server

- **依赖名称**：钉钉文档 MCP Server
- **安装地址**：https://aihub.dingtalk.com/#/detail?instanceId=133591&detailType=instanceMcpDetail&mcpId=9629
- **必需权限**：钉钉文档查看权限

**检查机制**：
- Skill 执行前会自动检测 MCP Server 是否已安装
- 如果未安装，会提供详细的安装引导
- 安装完成后可正常使用所有功能

## 核心功能特性

1. **环境自动检查**：执行前自动检测钉钉文档 MCP Server 是否已安装，未安装时提供引导
2. **智能意图识别**：理解用户真实意图，区分核心实体和过滤条件
3. **权重关键词策略**：主次关键词区分，避免无效交叉聚合
4. **精准过滤搜索**：先搜核心词，再用条件词过滤，提升准确率
5. **全知识库检索**：搜索用户有权限的所有知识库，不限目录范围
6. **相关性评分**：基于标题匹配度、时间新鲜度、意图匹配综合评分
7. **自动保存**：结果超过 10 篇时，自动保存为本地 Markdown 文档
8. **详细卡片**：每个结果包含标题、类型、作者、时间、相关性评分、链接等完整信息

### 1. 参数解析

从用户输入中提取：
- **搜索内容**（必填）：用户的问题或关键词
- **特殊命令**：`--help`

### 2. 智能意图识别与关键词提取

**核心原则**：理解用户真实意图，区分主要搜索对象和辅助过滤条件

#### 2.1 意图识别策略

分析用户问题，识别以下要素：

1. **核心实体**（必选）：用户想了解的主要对象、概念、产品
   - 示例："支持计划"、"SWAT"、"监控"
   - 权重：**高**（用于主搜索）

2. **操作条件**（可选）：对核心实体的操作、流程、状态
   - 示例："开通"、"部署"、"续期"、"配置"
   - 权重：**中**（用于结果过滤）

3. **目标要求**（可选）：用户期望达成的目标或解决的问题
   - 示例："最佳实践"、"流程"、"方法"
   - 权重：**低**（用于评分参考）

#### 2.2 搜索策略选择

根据意图识别结果，选择最佳搜索策略：

**策略 A：单核心搜索**（最简单）
- 适用：用户输入已经是简洁关键词
- 示例：`"支持计划"` → 直接搜索

**策略 B：核心+过滤搜索**（最常用）⭐
- 适用：用户问题包含核心实体 + 操作条件
- 示例：`"支持计划如何开通"`
  - 核心实体：`支持计划`（权重高）
  - 操作条件：`开通`（权重中）
  - 搜索流程：
    1. 搜索核心词 `"支持计划"`
    2. 从结果中过滤包含 `"开通"` 的文档
    3. 如果过滤后结果 < 3 篇，扩大范围（标题或内容包含即可）

**策略 C：多核心并行搜索**（复杂问题）
- 适用：用户问题包含多个独立的核心概念
- 示例：`"SWAT和监控的区别"`
  - 核心实体 1：`SWAT`
  - 核心实体 2：`监控`
  - 搜索流程：
    1. 并行搜索两个核心词
    2. 交叉对比，找出对比类文档

#### 2.3 意图识别示例

| 用户问题 | 核心实体 | 操作条件 | 搜索策略 | 说明 |
|---------|---------|---------|---------|------|
| "支持计划如何开通" | 支持计划 | 开通 | B：核心+过滤 | 想了解支持计划的开通方式 |
| "SWAT部署流程" | SWAT部署 | 流程 | B：核心+过滤 | 想了解SWAT的部署流程 |
| "支持计划" | 支持计划 | 无 | A：单核心 | 直接搜索 |
| "客户支持计划续期怎么操作" | 客户支持计划 | 续期 | B：核心+过滤 | 想了解续期操作 |
| "SWAT和监控的区别" | SWAT, 监控 | 区别 | C：多核心并行 | 对比两个概念 |
| "最佳实践有哪些" | 不明确 | 最佳实践 | 需确认 | 意图不明确，需用户澄清 |

#### 2.4 关键词确认机制

**必要时向用户确认**：

当遇到以下情况时，应向用户确认意图：
1. **核心实体不明确**：无法识别主要搜索对象
2. **歧义问题**：用户问题模糊，可能对应多个不同概念
3. **专业术语**：不确定的缩写、代号、内部术语

**确认示例**：
```
🤔 我理解您的问题，提取到以下意图：
- 核心实体：支持计划（主要搜索对象）
- 操作条件：开通（用于过滤结果）

搜索策略：先搜索"支持计划"，再过滤包含"开通"的文档。

是否继续？或您可以提供更具体的描述。
```

### 3. 意图驱动搜索执行

#### 3.1 策略 A：单核心搜索

如果只有核心实体，无操作条件：
```
工具：mcp_MCP_search_documents
参数：
- keyword: <核心实体>
```

#### 3.2 策略 B：核心+过滤搜索 ⭐ **最常用**

**第一步：搜索核心实体**
```
工具：mcp_MCP_search_documents
参数：
- keyword: <核心实体>
```

**第二步：过滤结果**
```python
# 伪代码示例
# 1. 获取核心词搜索结果
core_results = mcp_MCP_search_documents(keyword="支持计划")

# 2. 过滤包含操作条件的文档
filtered_results = []
for doc in core_results:
    # 检查标题是否包含操作条件
    if "开通" in doc.name:
        filtered_results.append({
            "doc": doc,
            "match_type": "title_match",  # 标题匹配（高权重）
            "score_boost": 20
        })
    # 如果标题不匹配，获取文档内容检查
    elif check_doc_content_contains(doc.nodeId, "开通"):
        filtered_results.append({
            "doc": doc,
            "match_type": "content_match",  # 内容匹配（中权重）
            "score_boost": 10
        })

# 3. 如果过滤后结果 < 3 篇，放宽条件
if len(filtered_results) < 3:
    # 保留所有核心词结果，但降低操作条件匹配文档的评分
    filtered_results = core_results  # 扩大范围
```

**第三步：获取文档详情**
```
工具：mcp_MCP_get_document_info
参数：
- nodeId: <过滤后的文档ID列表>
```

#### 3.3 策略 C：多核心并行搜索

如果有多个独立核心概念：
```python
# 伪代码示例
keywords = ["SWAT", "监控"]
all_results = []

for keyword in keywords:
    results = mcp_MCP_search_documents(keyword=keyword)
    all_results.append({
        "keyword": keyword,
        "documents": results
    })

# 交叉对比，找出同时涉及两个概念的文档
```

**注意**：
- 不设置 limit 参数，获取全部搜索结果
- 核心词搜索优先，过滤词用于结果筛选

### 4. 获取文档详情

对所有搜索结果（去重后），批量调用：

```
工具：mcp_MCP_get_document_info
参数：
- nodeId: <文档的 nodeId>
```

**提取信息**：
- 文档标题 (name)
- 文档类型 (contentType, extension)
- 创建者 (creator) - 如果有
- 创建时间 (createTime)
- 更新时间 (updateTime)
- 访问链接 (基于 nodeId 构建)

### 5. 结果聚合去重

#### 5.1 去重规则

- 按 `nodeId` 去重
- 同一文档在多次搜索结果中出现时，保留最高评分
- 记录匹配的关键词列表

#### 5.2 匹配类型标记

- 🔥 **直接匹配**：文档标题或内容包含完整关键词
- 📎 **多词匹配**：文档在多个关键词的搜索结果中出现

### 6. 相关性评分

**简化评分算法**（只基于标题和时间）：

#### 6.1 标题匹配评分（0-80 分）

| 匹配类型 | 评分 | 说明 |
|---------|------|------|
| 完全包含关键词 | +80 | 标题中包含完整关键词 |
| 分词后部分匹配 | +50 | 标题包含关键词的部分词汇 |
| 语义相关 | +30 | 标题与关键词语义相关 |

#### 6.2 时间新鲜度评分（0-20 分）

| 更新时间 | 评分 | 说明 |
|---------|------|------|
| 7 天内 | +20 | 非常新的文档 |
| 30 天内 | +15 | 较新的文档 |
| 90 天内 | +10 | 近期文档 |
| 180 天内 | +5 | 半年内文档 |
| 超过 180 天 | +0 | 较旧的文档 |

#### 6.3 总分计算

```
总分 = 标题匹配评分 + 时间新鲜度评分
最高分：100 分
```

### 7. 综合排序

**排序规则**：
1. **第一排序维度**：相关性评分（降序）
2. **第二排序维度**：`updateTime`（更新时间，降序）
3. **第三排序维度**：`createTime`（创建时间，降序，当 updateTime 为 null 时）
4. 无时间信息的文档排在最后

### 8. 判断输出方式

- 如果结果数量 **≤ 10 篇**：直接在对话中展示
- 如果结果数量 **> 10 篇**：保存为本地 Markdown 文档，并在对话中提示

## 关键词提取示例

### 示例 1：简单问题
**用户问**：`"支持计划如何开通"`

**提取**：
- 核心名词：`支持计划`
- 关键动作：`开通`
- 关键词列表：`["支持计划", "开通"]`

**搜索策略**：
1. 搜索"支持计划" → 获取所有相关文档
2. 搜索"开通" → 获取所有相关文档
3. 合并去重，优先展示同时匹配两个词的文档

### 示例 2：复杂问题
**用户问**：`"客户企业顶级支持计划续期流程是什么"`

**提取**：
- 核心概念：`客户支持计划` 或 `顶级支持计划`
- 关键动作：`续期`
- 关键词列表：`["客户支持计划", "顶级支持计划", "续期"]`

**搜索策略**：
1. 并行搜索 3 个关键词
2. 合并结果，去重
3. 评分时，匹配"客户支持计划"+"续期"的文档评分更高

### 示例 3：专业术语
**用户问**：`"SWAT部署的最佳实践"`

**提取**：
- 核心术语：`SWAT`
- 关键概念：`部署`、`最佳实践`
- 关键词列表：`["SWAT部署", "最佳实践"]`

**搜索策略**：
1. 搜索"SWAT部署" → 精确匹配
2. 搜索"最佳实践" → 补充相关文档
3. 合并结果

### 示例 4：需要确认
**用户问**：`"HI怎么用"`

**分析**：
- "HI" 可能是缩写、产品名、内部术语
- 问题过于简单，可能有歧义

**确认话术**：
```
🤔 您提到的"HI"是指：
1. 某个产品或工具的名称？
2. 还是有其他含义？

建议提供更具体的关键词，例如：
- 如果是产品名："HI工具使用"、"HI平台"
- 如果是流程："HI接入流程"、"HI配置方法"

请确认或提供更详细的描述。
```

## 注意事项

1. **单一接口**：仅依赖 `search_documents` 接口，搜索范围为用户有权限的所有知识库
2. **精准匹配**：该接口对标题和文章内容进行精准匹配，无需额外的语义扫描
3. **关键词精简**：关键词应精简且能概括用户问题，避免过长或过于具体
4. **多词并行**：多个关键词并行搜索可提升查全率，但注意不要超过 3 个关键词
5. **结果去重**：同一文档可能在多个关键词的搜索结果中出现，需按 nodeId 去重
6. **评分简化**：评分只基于标题匹配度和时间新鲜度，不需要获取文档内容
7. **自动保存**：结果 > 10 篇时自动保存为本地 Markdown 文档
8. **保存路径**：所有搜索结果保存在 `search-results/` 目录下
9. **文件名规范**：`search-<关键词>-<YYYY-MM-DD>.md`，避免冲突可添加序号
10. **权限检查**：如果搜索返回空结果，可能是用户无访问权限
11. **关键词确认**：遇到歧义或不确定的术语时，应向用户确认
12. **批量获取**：获取文档详情时，可并行调用 `get_document_info` 提升性能
13. **错误处理**：所有 MCP 工具调用失败时，给用户友好的错误提示
14. **性能优化**：由于只使用 search_documents 接口，搜索速度通常 < 2 秒

## 工具依赖

- `mcp_MCP_search_documents` - 搜索文档（唯一搜索接口）
- `mcp_MCP_get_document_info` - 获取文档详情
- AI 关键词提取 - 从用户问题中提取核心关键词
- 文件系统读取 - 读取 config.json（可选）

## 与 V1 的对比

| 特性 | V1（双引擎版本） | V2（简化版本） |
|------|----------------|---------------|
| **搜索接口** | search_documents + list_nodes | 仅 search_documents |
| **搜索范围** | 指定目录 | 全知识库（用户有权限的所有目录） |
| **关键词策略** | 单关键词 + AI扩展 | 多关键词并行搜索 |
| **缓存机制** | 需要本地缓存 | 无需缓存 |
| **API调用** | 大量（遍历目录） | 少量（仅搜索） |
| **搜索速度** | 3-5 秒（首次） | < 2 秒 |
| **复杂度** | 高（双引擎+缓存） | 低（单一接口） |
| **维护成本** | 高 | 低 |
| **查全率** | 高（但依赖缓存） | 高（多关键词覆盖） |
| **适用场景** | 大规模知识库 | 日常快速检索 |

## 性能优势

1. **速度提升**：从 3-5 秒降低到 < 2 秒
2. **API 调用减少**：从数十次降低到 2-5 次
3. **无需缓存**：简化架构，降低维护成本
4. **搜索范围更广**：不局限于单一目录，覆盖全知识库
5. **查全率保障**：多关键词并行搜索，覆盖不同匹配场景
